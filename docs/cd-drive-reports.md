# CD drive report and position contract

Related to #45 and #17. Written from the primary contract before implementation
or new oracle execution. Original synthetic media only.

## Primary references and revision reconciliation

The later Sega [CD communication interface §7.2.5(3–5)](https://www.infochunk.com/saturn/segahtml_en/prgg/sysg/cdif/hon/p07_11.htm#no5_03)
defines reports; §7.2.4(1) defines Q. In
[ST-162-062094](https://antime.kapsi.fi/sega/files/ST-162-062094.pdf), those are
§7.2.4, printed pp.59–61 (PDF pages 47–49), and §7.2.5, printed p.62
(PDF page 50), respectively. They agree on the validity table and home/error
retention. ST-162 §4.2 pp.37–38 explains stop/standby; §4.3 p.39 permits Q
queries in every drive state, including OPEN. This removes the inherited blanket
OPEN rejection for Q. It does not grant TOC/session access with the tray open.
The later R–W buffer capacity revision is outside this increment.

## Report table

Each row describes report bytes after the status byte; transfer commands may
replace report fields with their documented payload. `FF` means invalid.

| Drive state | Flag/repeat | Control/ADR, track, index | 24-bit FAD |
| --- | --- | --- | --- |
| PAUSE, PLAY, SCAN, RETRY | Current | Current | Current |
| SEEK | Current (ROM flag clear) | Target | Target |
| STANDBY after pause timeout | Retained paused value | Retained paused values | Retained paused position |
| STANDBY after Seek Home | FF | FF, FF, FF | FFFFFF |
| OPEN, NODISC, ERROR | FF | FF, FF, FF | FFFFFF |
| BUSY | Current or invalid; transition dependent | Current or invalid | Current or invalid |
| FATAL | Undefined | Undefined | Undefined |

BUSY and FATAL are not generated by this functional drive. No exact oracle or
new transition phases are invented for either. PAUSE's existing ROM flag
convention is retained; the later manual defines that flag's meaning in PLAY.
Command REJECT reports are invalid; WAIT reports retain the applicable state.
Startup remains the separate `0043 4442 4C4F 434B` signature.

## Retention and transitions

- A timed ordinary standby keeps the paused position and complete report.
- Seek Home stops the drive and marks a separate home position. It preserves
  the play range, maximum repeat and notification count. PAUSE from home seeks
  to FAD 150; an explicit seek uses its requested target.
- ERROR hides the report without destroying the last position, range or repeat
  count. PAUSE recovers the retained position. A new explicit play/seek can
  recover on the same media. Invalid query bytes never enter this internal state.
- Repeat notifications survive seek and tray transitions. Explicitly changing
  the play range or maximum repeat clears the notification count; the unchanged
  maximum encoding preserves it.
- Q acquisition returns five words without CRC. Its control/track/index and
  absolute position follow report validity. For valid ADR=1 data the relative
  address is distance from track start; in invalid states position fields are
  FFFFFF, with the format's fixed separator byte zero. The invalid control/ADR
  byte is FF, so no meaningful ADR=1 position is asserted in those states.
- At disc-end completion the current report and Q identify lead-out (track AA,
  index 1, relative address zero at the boundary), using the last track's
  CONTROL/ADR. This follows ST-162 §4.2 p.37 and §7.2.5 p.62.

## Bounded timing conventions

Keep existing functional command latency (1075 reference clocks), seek latency
(26875), drive ticks (75 Hz audio/scan, 150 Hz default data), and stopped report
cadence (60 Hz). These are bounded deterministic envelopes, not measured
mechanical waveforms. At a coincident deadline drive/seek/timeout advancement
precedes periodic generation, and command completion follows it. A pending
command suppresses periodic register replacement; an unread command response is
protected until CR4 is read. SCDQ is raised even while publication is protected;
HIRQ acknowledgement and masks remain independent. Reset/power cancellation
must discard pending home/error/query publications. Tests inspect before, at
and after deadlines, compare advancement chunks 1/3/17/10000 and passive reads,
and use literal register/Q expectations rather than production report helpers.
