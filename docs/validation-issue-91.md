Related to #91 and #17. This records the bounded runtime hardware increment;
it does not establish complete Saturn/CD conformance. See the

## Inherited-main negative oracle

The final original application and native oracle were run with production
`src/cd.rs` from `db96e2d90826e22d6f3568af478ae9b44fd2e27e` (the selected
checkpoint inherits this code). Every other production file is unchanged by
this increment. A `try/finally` restored the corrected file after the probe.
The test was not marked ignored or changed to expect failure.

```text
cargo test --locked --test cd_runtime \
  same_application_reads_all_bytes_and_independent_handles_in_two_layouts_and_cold_restarts \
  -- --nocapture

pc 06020B28, phase 2, trace end 26072320, host words 2, CD words 2
left: 57489       # E091
right: 24589      # 600D
1 failed; 0 passed; execution 1.52 seconds; exit 101
```

The firmware already loaded all 16433 application bytes, entered AIP, initialized
the drive, resolved DATA/ALPHA/BETA from real directory bytes, selected FID2 and
acquired actual file data. The first three-byte read consumed two FIFO words;
DataEnd returned 2. ST-162 §8.2.1 function1.10 requires a larger CD-side count for
an interrupted GET. The guest stops before committing its handle cursor. The
one-word offered-FIFO policy now applies to all GET classes, returning 3 here;
normal and excess transfers remain capped, and PUT retains exact host counts.
The unchanged guest/oracle passes with the production correction.

To reproduce independently, use a disposable worktree at `db96e2d`, copy this
revision's `tests/cd_runtime.rs` and the four `cd-runtime` fixture outputs into
that checkout, and run the command above. No proprietary assets or modified
firmware are needed. The inherited source's only behavioral difference for this
trace is the old `t.rw.is_some()` prefetch condition in DataEnd, replaced by
`t.put.is_none()`.

## Corrected exploratory failures and environment

The first guest-builder attempts exposed mistakes in the new fixture: a record
pointer overwritten by its own diagnostic store, a filter left restricted by
prior directory work, and deletion of an already empty partition. The builder
now preserves the pointer, explicitly resets its raw-read filter, and queries
remaining sector count before suffix deletion. These are guest software fixes;
they were corrected before capturing the inherited-main E091 oracle.

Existing partial GET counts in CD drive/copy/Q tests and DMA startup vectors
previously equated the CD count with host consumption. Focused checks and the
first full native run exposed these assumptions (the latter stopped at three
library-test failures). Only their DataEnd count expectations were corrected:
one offered CD-side word, including the zero-host-word case. Their complete
payload, source-unit publication, ordering, IRQ, timing and mutation checks
remain. No failing test was dropped or retried blindly. Stable Rust 1.99 Clippy also
requested a new fixed-size chunk API in the added native pixel assertion. It
was replaced by equality against the complete 320×224 RGBA expectation, which
also checks the full frame length; native/Wasm Clippy then passed. The complete
native suite was rerun after that correction.

The first web build selected Homebrew Rust 1.94 through the shell PATH and could
not find Rustup's Wasm core. Selecting Rustup stable's compiler and Cargo together
fixed it. npm dependencies and Playwright's pinned Chromium were initially absent.
After `npm ci`, a shared browser-cache installation lock held up installation;
this task's installer was stopped and restarted with an isolated ignored
`target/issue-91/browsers` cache. No unrelated installer or shared cache was
modified. Playwright's ZIP extraction process then stalled on this host with a complete archive;
the task's own installer was stopped, and the exact pinned 145.0.7632.6 browser
ZIPs were extracted with macOS `ditto` into that same isolated cache. Neither
browser version nor test timeout was changed. Temporary PDF readers, downloaded
primary manuals, build/test logs and
browser binaries live only under ignored `target/`; they are not shipped.
